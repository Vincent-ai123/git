# 个人计算机知识体系架构

> 数据版本：2026-10-19。依据两份 2026-10-17 学习路线整理，服务于个人实习准备。

当前体系包含 **6 个岗位方向、8 个大概念、30 个模块、69 个技能、345 项具体学习内容、122 条前置关系、12 份官方 JD 样例**。每个技能回答“是什么、学哪些、为什么学、先学什么、后续用在哪、怎样验证”。

## 按范围逐层展开

知识地图的浏览层级为：**大概念 → 模块 → 技能 → 具体学习内容**。

| 大概念 | 模块示例 | 对应路线 |
|---|---|---|
| 开发工具与工程习惯 | 终端与版本管理、构建与协作、测试与调试 | 阶段 0，全程复用 |
| C++ 与计算机基础 | 程序设计、现代 C++ 与内存、数据结构与算法、体系结构 | 阶段 1 |
| Linux、操作系统与网络 | Linux 与操作系统、网络与 I/O、并发、性能分析 | 阶段 2 |
| 数据库、后端与数据平台 | SQL 与建模、API 服务、缓存消息、数据管道、部署监控 | 阶段 3、阶段 6 |
| 交易系统与量化研究 | 金融市场与事件、订单簿与回放、回测与研究设计 | 阶段 4；研究为阶段 9 长期补充 |
| Python、统计与机器学习 | 数据处理、概率数学、可信评估、PyTorch | 阶段 5 |
| Agent、RAG 与 AI 应用 | 模型 API、检索、工具调用与评测 | 阶段 7 |
| GPU 与 AI 基础设施 | GPU 执行与内存、CUDA / Triton、推理服务 | 阶段 8，完成主线后选修 |

例如打开“交易系统与量化研究”，先看到三个模块；再打开“订单簿与回放项目”，看到订单簿、事件回放两个技能；点击技能才进入具体内容与学习详情。所有技能与具体内容不会一次铺在首页。

这四个浏览层级表达范围大小。技能另有工具基础、工程系统、数据 AI、方向分支四种分类，用于跨概念筛选；分类不等于学习顺序。主线顺序与并行安排由路线阶段和前置依赖共同决定。

## 岗位范围与学习顺序

保留 C++ 系统与量化开发、金融科技后端、通用后端与数据平台、AI 应用 / Agent / RAG、量化研究、AI 基础设施 / GPU 系统。

共同底座按 **现代 C++ → Linux / 操作系统 / 网络 → SQL / 数据库 → 行情回放与订单簿 → Python / 统计 / 机器学习**推进，再选择一个后端或 AI 应用作品。阶段 0 的 Git、构建、测试和调试贯穿全程；数据库可与系统阶段交叉练习。

量化研究是长期补充，GPU 是完成主线后的选修探索。前端、移动端、安全、嵌入式等独立入口已移除；仍对后端有用的安全、容器和监控保留在相应模块。避免为了覆盖所有岗位而同时启动全部分支。

每个岗位的路径按“先修基础 → 岗位核心 → 项目验证 → 进阶方向”组织。语言替代组由目标 JD 决定：金融科技后端可选 Python / Java / Go，通用后端还可选 C++，GPU 可选 CUDA / Triton；共校验 12 种路径组合。AI 应用以 Python 为主线，不要求先完成全部机器学习课程。

核心作品是 C++ 行情回放与订单簿实验室：价格与时间优先、撤单与部分成交、数量守恒、重复/乱序事件、确定性回放，以及有机器和编译条件说明的性能报告。不能用节点数量代替能运行、能解释和能验证的作品。

## 节点和连线的含义

- 概念和模块是范围入口，点击展开；技能是可学习与验证的能力单元，具体内容是技能内部的细分索引。
- 箭头由“前置”指向“后续”。概念和模块层的边汇总其成员之间的依赖，不代表分组内部每项都要先学完，也可能出现分组间双向汇总；技能级依赖必须无环。
- `prerequisites` 是显式建模的先修建议，不声称穷尽背景知识，也不是企业统一门槛。技能详情始终列出具体前置技能，跨模块关系可直接跳转。
- 选择岗位后只保留相关技能、所选技术栈和前置知识所在的分组；浏览补充技能不会将它变成岗位必修项。前置链模式保持分组导航，只展开所选技能及其递归前置项。
- 颜色帮助区分知识范围，节点同时保留文字标签；技能进度通过文字和完成符号表示。

## 交互与可访问性

球体使用真实三维坐标、透视投影和深度排序，通过 SVG 渲染少量当前层节点。文字标签自动避让，并用引线对应到球面位置；调整屏幕大小时同步更新文字排版。可自动旋转，鼠标/触屏拖动或方向按钮旋转，按钮或键盘 `+` / `-` 缩放，`Home` 复位，`Enter` / 空格激活节点。普通滚轮继续滚动页面；Ctrl / Command 加滚轮用于球体缩放。

悬停或聚焦球体时暂停自动旋转；有显式暂停按钮。系统启用减少动画时不自动旋转，离屏或页面隐藏时停止绘制。手机纵向手势用于页面滚动，初次打开默认显示分层清单，可切回图谱。

图谱与清单共用同一层的节点和依赖。每层保留面包屑、返回上层；浏览器前进/后退也恢复层级。展开概念/模块后聚焦层级标题，激活技能后聚焦详情标题。完整索引默认折叠，需要搜索或逐项记录时再展开。

## 数据模型与维护

`data.js` 是唯一的数据来源。`domains` 包含概念与模块，模块列出 `skillIds`；每个技能恰好归属一个模块和一个概念。技能 ID 保持稳定，记录范围、学习理由、具体内容、先修项、验证成果和岗位映射。

岗位数据分开保存核心 `must`、技术栈替代组 `mustOneOf`、加分 `preferred` 和路径 `path`。`getLearningPath(roleId, choices)` 递归补齐依赖并排序，进阶项按兴趣选择。更新数据时检查所有路径变体，不把所有替代栈塞进同一条必修路径。

新增内容先判断属于现有技能的具体内容、一个新技能，还是需要新模块；避免把相近词都变成首页节点。新增依赖时说明为什么需要这项基础；仅有主题关联不应自动连边。

## 招聘证据与个人记录

通用岗位画像与逐职位 JD 证据分开维护。12 份样例主要来自海外与香港，包含相邻研究岗和方向汇总；不能据此推算中国内地市场热度、统一资格或实时开放状态。未映射到当前路线的原文要求仍保留，并明确它未在本体系展开。研究岗的博士条件只适用于对应 JD。

投递时逐条核对在读状态、毕业年份、专业、连续实习时间、每周出勤、地点、语言和工作许可。来源可读取只表示核查时可用；来源核查日期与本次界面更新日期分别记录。

学习进度使用原有 `career-skill-atlas-progress-v1`，继续读取保留技能的旧记录；导入合并已知技能，拒绝非法格式或状态。状态包含未开始、学习中、可以讲清、实现并验证，只是个人学习记录。进度与技术栈选择不会随分享链接发送。

地址参数 `role`、`domain`、`module`、`skill` 保存当前浏览位置。旧岗位别名 `quant-dev`、`data-engineer` 分别转到 C++ 系统与量化开发、通用后端与数据平台；未知参数安全回到可用的总览。

运行 `npm test` 校验层级归属、ID 和引用、无环依赖、全部路径变体、分层导航、球体交互、旧进度及多尺寸布局。`npm run build:docs` 同步岗位、分层知识网络和 JD 文档；`npm run check:sources` 单独联网复核原文。
