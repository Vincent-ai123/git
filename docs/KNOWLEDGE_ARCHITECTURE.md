# 计算机实习知识体系架构

> 数据版本：2026-10-18。该体系服务于个人能力规划，岗位与技能关系是可修改的建模结果，不是雇主认证的课程表。

## 架构原则

这套知识体系按“基础可复用、工程能交付、项目可验证、方向再专精”组织。岗位目标决定哪些知识要加深；不能把技能节点数当成竞争力，也不用为了覆盖所有岗位而学完每条分支。

四个层级：

1. **工具与基础**：Shell、Git、构建和测试、调试、算法/数据结构、编程语言、SQL。
2. **工程与系统**：Linux、操作系统、并发、网络、数据库、服务/API、质量、部署、云平台、数据工程。
3. **数据与 AI**：统计、分析、机器学习、深度学习、特征工程、评估、RAG 和模型服务。
4. **岗位分支**：Agent、GPU、量化研究与交易、嵌入式、移动端、安全和其他专项知识。

## 图中的关系语义

- 圆点代表一个可以单独学习、练习和验证的知识单元。
- 颜色代表架构层级：蓝色是基础，绿色是工程系统，紫色是数据与 AI，橙色是岗位分支。
- 箭头由先修项指向依赖它的后续项。比如“操作系统 → 并发与同步”表示先理解进程/线程等基础，再深入同步机制。
- 节点的 prerequisites 是显式建模的学习前置项，不声称覆盖了所有潜在背景知识；没有前置项的节点仍可能需要数学、英语或编程基础。
- 岗位面板中的“常见核心能力”是优先准备的能力组，不是每份 JD 都会逐项要求；“任选一条技术栈”是替代路径；“加分/进阶能力”按具体招聘描述决定是否学习。
- 选择岗位后，知识图高亮该岗位的能力，并补出依赖这些能力所需的前置知识。点击节点可查看学习理由、前置项、验证成果和关联岗位。

## 共同底座与典型主线

开发工具与版本管理
→ 语言与数据结构
→ Linux、操作系统、并发、网络
→ SQL、数据库和 API
→ 能测试、运行和复现的项目
→ 根据目标选择工程、数据/AI、云平台或专项分支。

这条主线是结构提示，不是所有岗位都必须完全按顺序学习。例如前端方向可以在 Git 和语言基础后较早练习 HTML/CSS；数据分析可并行起步 SQL 和统计；GPU 专项则要补数学和体系结构。

## 岗位方向簇

### 软件与系统

后端、前端、全栈、移动端、C++/系统、测试开发、嵌入式/IoT、量化开发。

- 共用：至少一门主力语言、Git、调试、测试和数据结构/算法。
- 服务工程继续学习 API、网络、数据库、并发、部署和故障定位。
- C++/系统和量化开发更常把生命周期、资源、并发和性能作为作品或面试重点。
- 移动端和嵌入式有明确平台或设备分支；无需同时学完所有平台。

### 数据与 AI

数据工程、数据分析/BI、机器学习工程、算法/机器学习算法、Agent/LLM 应用、量化研究。

- 共用：Python、SQL、数据质量、统计/实验意识和结果可复现。
- 数据工程更偏 ETL、建模、批流和质量；分析岗位更偏指标口径、SQL、可视化和沟通。
- ML/算法岗位更偏数据、模型、评估和实验；AI 应用更偏检索、工具、评测和安全控制。
- 量化研究是基于金融/市场数据的研究工作，必须显式处理样本外验证、交易成本和数据泄漏。

### 云与基础设施

云平台/DevOps/SRE、AI 基础设施/GPU 系统。

- 共用：Linux、网络、脚本、构建、容器和性能/运行监控。
- 平台/SRE侧重部署、可观测性、自动化、可靠性和权限成本。
- AI 系统/GPU侧重 C++、并行执行、访存、运行时和有证据的性能优化。

### 安全与终端

网络安全/安全工程与嵌入式/IoT 横跨多层基础，但工作环境和约束各异。

- 安全工作要求授权范围、风险证据、修复建议与回归验证。
- 设备端工作要求硬件接口、受限资源、调试方法和实时/协议约束。

## 以岗位为中心的学习与求职

1. **先定目标范围**：选择 1 个主岗位和 1 个相邻备选方向；保存 3—5 份目标地区的真实实习 JD。
2. **先核实申请资格**：毕业年份、在校状态、实习时间、每周到岗天数、地点和专业限制可能是硬门槛。
3. **从 JD 抽取可核实字段**：岗位职责、必须技能、偏好技能、资格条件、语言栈、团队产品和申请周期；保留原文链接与核查日期。
4. **对照知识网络**：核心要求映射到知识节点；前置节点标成基础，偏好项标成加分，JD 未提到的通用知识不能自动升级为必须要求。
5. **选择能闭环的作品**：优先做一个能展示、能运行、能测量、能解释的项目；把关键贡献和验证证据对应到目标岗位。
6. **根据反馈迭代**：真实 JD、面试反馈和技术任务比收藏课程数量更能帮助调整学习优先级。

## 实习资格核验清单

| 字段 | 需要确认的问题 |
|---|---|
| 学籍与学位阶段 | 是否要求在读本科/研究生，是否排斥毕业生或特定培养项目 |
| 毕业窗口 | 预计毕业年月是否在职位规定区间 |
| 专业 | 是否限定计算机、软件、数学、统计、电子/通信等相关专业 |
| 可实习周期 | 是否要求连续数月，何时到岗，能否全职 |
| 每周出勤 | 现场或混合办公，每周最少到岗天数 |
| 地点与授权 | 城市/办公室、工作许可、语言要求和跨境/远程限制 |
| 招聘批次 | 职位是否开放、截止日期、申请次数和是否已停止接收 |

## 如何维护这张个人地图

- 新增技能时，给稳定 ID、解释、学习理由、层级、先修项和可验证的练习出口。
- 添加关系时先说明“为什么 A 是 B 的先修”；避免仅因概念有关联就连边。
- 添加岗位时区分共同核心、技术栈替代方案和加分项，并补充实习生可能完成的交付。
- 记录来源时保存原始招聘链接、公司/团队、地区、发布日期或核查日、职位原文和过期状态。
- 招聘描述随批次变化；通用能力图需要独立于过期职位记录保存。
- 维护数据后运行 npm test，确认节点/引用存在、ID 唯一且先修图无环。

站点的详细岗位画像由 ROLE_REQUIREMENTS.md 从 data.js 生成。交互式节点和岗位映射同样来自 data.js，避免知识地图与文档使用两套不同的数据源。
