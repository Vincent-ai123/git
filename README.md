# Career Skill Atlas · 计算机实习知识地图

[打开交互网站](https://vincent-ai123.github.io/git/) · [岗位要求与学习路径](docs/ROLE_REQUIREMENTS.md) · [完整知识点与依赖网络](docs/SKILL_NETWORK.md) · [官方 JD 样例](docs/JD_EVIDENCE.md)

从目标岗位倒推学习范围，把知识点、前置依赖、项目验证和实习要求连成一套个人计算机知识体系。

当前版本（2026-10-18）包含 **17 类岗位、83 个技能节点、415 个具体知识点、142 条前置关系、18 份官方招聘样例**，支持 26 种技术栈选择的学习路径。所有岗位、节点、关系和生成文档共用 `data.js`，便于持续扩展。

## 可以用它做什么

- **拆解岗位**：查看常见实习交付、核心能力、可替代技术栈、加分项、作品证据和面试关注点。
- **理解知识体系**：按基础、工程、数据/AI、岗位分支浏览，搜索可直接定位到具体知识点。
- **探索知识网络**：选择岗位查看相关节点与前置项；点击节点查看为什么学、学哪些、适配岗位和如何验证。支持前置链聚焦、层级筛选、缩放、内部滚动、鼠标拖动和方向按钮。
- **切换文本关系清单**：与图谱共用相同节点，逐项阅读前置依赖；手机默认使用清单。
- **排列学习顺序**：目标岗位与主力技术栈联动，自动补齐依赖并排序，按“先修基础 → 岗位核心 → 项目验证 → 进阶方向”组织。选择 iOS 不强制 Android，选择 TypeScript 的 AI 应用路径不强制 Python。
- **对照真实招聘原文**：展开 JD 查看地区、资格时间、明示技能、加分项、短摘、核查日期和官方链接；支持按关联方向筛选。
- **记录个人进度**：标记未开始、学习中、可以讲清、实现并验证；保存在当前浏览器，可导出 JSON 并在其他设备导入合并。
- **保存选择**：地址中的 `role`、`skill` 参数保留岗位与节点，方便收藏或分享；按 `/` 聚焦搜索。

## 岗位范围

后端、前端、全栈、C++/系统、移动端、测试开发、数据工程、数据分析/BI、机器学习工程、算法/机器学习算法、AI 应用/Agent、云平台/DevOps/SRE、AI 基础设施/GPU、网络安全、嵌入式/IoT、量化开发、量化研究。

这些方向未按招聘数量排名，部分属于专项分支。岗位画像是可调整的通用准备建议；每份 JD 的明示要求独立列出。量化开发画像以 C++ 系统路径为例，官方样例同时展示 OCaml/Python 等不同路线。

## 招聘证据与适用范围

18 份样例来自 Databricks、Stripe、Cloudflare、Datadog、NVIDIA、Verkada、Jane Street 的官方公开招聘系统。样本主要来自海外与香港，包括相邻研究岗位和多方向汇总，不能据此推算中国市场热度或统一学历门槛。

每份记录保留原文链接、公开 API、资格、技能职责、加分项、短摘和核查日期。“原文可读取”只描述核查时的来源可用性；投递前仍需复核岗位是否开放、毕业窗口、地点、语言、实习时长与工作许可。研究实习的博士条件只适用于对应职位，不能套用到 AI 应用工程。

职业词典和趋势资料用于背景理解，公司搜索入口用于查找职位，技术文档用于后续学习；三类资料均不替代具体 JD。详细出处与边界见 [JD_EVIDENCE.md](docs/JD_EVIDENCE.md)，最近一次自动复核见 [EVIDENCE_STATUS.json](docs/EVIDENCE_STATUS.json)。

## 在本机运行

使用 **Node.js 22 或更新版本**，无需安装第三方依赖。

```sh
npm run dev
```

打开终端给出的地址，默认是 `http://127.0.0.1:4173`。网页本身使用原生 HTML/CSS/JavaScript，不依赖 Node.js；Node.js 仅用于本地预览、生成文档和验证。

```sh
npm test                 # 数据、路径、文档生成和真实浏览器交互检查
npm run check:sources    # 联网复核 18 份官方来源和原文短摘
npm run build:docs       # 重新生成岗位、知识网络、JD 文档
```

浏览器检查默认使用 Windows 上的 Microsoft Edge，可通过 `EDGE_BIN` 指定其他 Chromium 浏览器。它使用独立临时配置，不操作日常浏览器；没有可用浏览器时会明确失败。截图保存在临时预览目录，可通过 `ATLAS_SCREENSHOT_DIR` 指定位置。

## 知识模型

技能节点包含稳定 `id`、层级 `layer`、具体知识点 `topics`、前置项 `prerequisites`、范围 `summary`、学习理由 `why` 和验证出口 `proof`。`directRoleIds` 表示直接使用，`roleIds` 还包含前置复用。

岗位画像把核心能力 `must`、替代组 `mustOneOf`、加分能力 `preferred` 与独立路径 `path` 分开维护。`getLearningPath(roleId, choices)` 根据选择递归补齐依赖并排序；进阶节点按兴趣和具体 JD 决定是否深入。

JD 记录独立于通用画像，保存原文明示条件及本站的知识映射。详情见 [知识体系说明](docs/KNOWLEDGE_ARCHITECTURE.md)。

## 验证与部署

自动检查覆盖全部路径的依赖顺序、岗位/节点引用、无环关系、实际资源加载、搜索、技术栈替换、图谱与清单一致性、键盘选择、JD 展开、进度重载/导入导出、低动态偏好及 375/390/768/1024/1440 宽度布局。招聘来源复核单独联网执行，不与离线页面测试混用。

GitHub Pages 从 `main` 分支根目录发布，`.nojekyll` 保持静态资源直接可用。修改数据后运行验证并提交；生成文档应由脚本更新，避免手动改出两套内容。

## 继续扩展

先选一个主修方向，以具体目标地区的 JD 调整优先级。后续可逐节点增加学习资源、练习、复习日期和个人项目证据；也可以补充中国内地公开实习样例并保留原文、批次和核查日期。当前阶段先把“学什么、为什么学、先后关系和验证方式”连起来。
